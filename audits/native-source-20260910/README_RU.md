# Нативный маршрут self-rewrite: WITHHOLD

База исследования: `2eeed3a787f76b7f2f1b4d14de3fde62e5a7b491`, ветка `yado-architecture-shadow-search`. Изменения подготовлены в отдельной ветке `yado-native-self-rewrite-20260910`. Canonical и evolution-ledger не изменялись.

Подтверждённая исходная ошибка: запрос с внешней задачей сохранялся в отчёте, но выбор действия получал только `self_selected_priority` из старого self-audit. Поэтому выбирался `EXPERIENCE_EVIDENCE_REVIEW`. Контроллер self-rewrite также игнорировал свой отдельный request и обращался к внешним coding-моделям. Базовые данные и результат вызова прежнего селектора сохранены в `baseline.json`; внешние модели в диагностике не вызывались.

Изменения:

- Контроллер читает актуальный rewrite request, требует `NATIVE_SEMANTIC_AST_ONLY` и запрещённый fallback. Вызовы внешних coding-моделей удалены из этого контура.
- Транспорт приёма запроса передаёт `task.task_id`, исходный `task.goal` и условия успеха в выбор приоритета. Блокирующие замечания аудита сохраняют преимущество. Неблокирующий legacy audit откладывается, сохраняясь в квитанции.
- Лексическое совпадение с описанием старого действия не считается доказательством выполнения нового контракта. Неподдерживаемая внешняя задача остаётся явным дефицитом с исходным идентификатором.
- Из V18 выделен повторно используемый AST-материализатор. Операнды V12, контекст V17, anchor и target берутся из существующих артефактов YADO. Проверяются хеши, точный parent source и область применимости. Новый оператор редактирования приёма целей здесь не написан.
- Тот же файл fresh/regression gate теперь проверяет текущий native-маршрут, а не старый LLM-repaired controller. Нет переноса старой квитанции в новый запуск: проверяются идентификатор запуска, текущий request, исходники, canonical и ledger.

Результаты локального запуска — `fresh-gate.json`:

| Проверка | Результат |
|---|---|
| 21 прежний regression-тест gate + 15 новых тестов | 36/36 PASS, без пропусков |
| compileall runtime | PASS |
| Canonical invariant guard | PASS, `canonical-guard.json` |
| Запуск native-контроллера с запрещёнными сетевыми соединениями | PASS |
| Свежая цель сохранена как активный дефицит | PASS |
| Историческая сборка V12/V17/V18 из исходных генов | Побайтное совпадение с прежним кандидатом |
| Новый source для текущей внешней цели | НЕ СОЗДАН |
| Fresh candidate validation / native admission | НЕ ВЫПОЛНЕНЫ: нет подходящего кандидата |
| Общий fresh/regression gate | WITHHOLD |

При исторической проверке используется исходник из Git-коммита `0565a6d46d35302d5db907878a6dbbb154452b02`. Нативный материализатор заново создаёт source с SHA-256 `700d1a176560ba24d25e22ebab8b1aaf5725e53e8c1cf81d45aaeacd495dd422`. Это воспроизведение уже известного исправления `LIVE_RESOURCE_EVIDENCE_SCOPE`, не создание нового решения задачи развёртывания. Текущая V17-квитанция также имеет WITHHOLD; исторический PASS не заменяет проверку текущего контекста.

Граница авторства: транспорт подключения, приём запроса и тесты написаны Codex. Нельзя приписывать их самостоятельному изобретению YADO. Исторические AST-операнды и контекст не переписывались. Дефициты executive зарегистрированы в отдельном временном состоянии; это не изменение постоянного набора возможностей ядра.

Следующий отсутствующий механизм — `FRESH_GOAL_CONDITIONED_NATIVE_SEMANTIC_EDIT_GENESIS`: построение соответствующего свежей цели семантического оператора, его контекста и нового AST, затем причинная fresh-проверка и regression. Действующий оператор специализируется на условном статусе записи аудита и не выражает изменение приёма внешних целей. Неподходящий старый patch к новой цели не применяется. Автоматический допуск в main и deployment не выполняются.

Воспроизведение в полном checkout с установленными runtime dependencies:

```sh
python runtime/yado_g2_self_rewrite_repaired_controller_fresh_regression_gate_v1.py --output audits/native-source-20260910/fresh-gate.json
```

При текущем дефиците ожидается код завершения 2. CI также должен сохранять WITHHOLD как непройденный admission gate; успешные тесты транспорта не повышают статус ядра.
