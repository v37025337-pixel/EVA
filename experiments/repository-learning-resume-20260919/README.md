# Live repository learning with retained state

The first campaign continued the verified native checkpoint from main workflow
35451019074. The repaired run resumes campaign 35452077271, including its retained
web-research memory and its honest partial result. It restores the exact source overlay, manifest, archive and SQLite
journal, checks their hashes, and verifies the operational identity and old event
prefix before and after a new run. It does not create a fresh native identity.

The restored run exposed a real research defect: every previously visited host
was permanently excluded. This exhausted the official Ghidra sources on restart.
The repair prefers new hosts, then freshly revalidates known hosts if necessary.
Each current host counts once, and `new_independent_host_count` and
`revisited_hosts` distinguish fresh diversity from revalidation. Repeated reading
is not labelled novel knowledge. Three regression cases cover restored research,
new-host priority and the inability of one host to fake independent evidence.

`research-source-update.json` explicitly pins the old and new hashes of the
controller and its tests. The existing continuity mechanism admits precisely
that implementation change, retains the old journal and operational identity,
and appends an implementation-upgrade event. Unlisted source drift still fails.

The existing YADO mechanisms perform three public-network studies: Ghidra and
its graph-analysis documentation; the five connected developer repositories
(Hivemind, Hoppscotch, Dyad, Nexus Tools and free-for-dev); and the existing twelve
peer-system sources. The router emitter remains inherited YADO code. The report
compares it against the existing router on the same disclosed five-case suite;
zero improvement is reported as zero improvement. Peer marker matches establish
source availability and relevant vocabulary, not semantic comprehension.

The experiment also uses the real pinned Hivemind v1.17.1 CLI in a separate local
workspace. A goal selected from the kernel's state is delivered through MCP,
executed and checked by native cognition, then read back from the tracker. A
retry must preserve the goal ID and add no duplicate journal events. This is a
real tracker integration, not a conversation with model agents or an upstream
repository patch. The CLI release is checked against its published SHA-256.

Twenty further goals are selected by the existing endogenous controller. The
host provides the cycle count; the goal grammar is inherited and finite.
Research memory is restored from the predecessor when present, its exact event
prefix is retained, and it is roundtrip-checked separately. No causal transfer from web
reading to general native intelligence is asserted by these separate stages.

The workflow saves the full checkpoint and partial evidence even if a network
stage fails. `summary.json` distinguishes overall completion from partial
completion. `continuation-receipt.json` specifically attests native state
continuity, not success of every external learning stage. A later manual run can
use the new run ID and its exact artifact name to continue from that checkpoint.
The named initial source is deliberate: automatic selection of an arbitrary
latest artifact could silently change the predecessor.

The existing `yado-external-dev-self-development-v1.yml` workflow runs this
campaign once on its branch, and supports `workflow_dispatch` with `source_run`
and `checkpoint_name` after admission. Its original mode remains available when
`source_run` is empty. No new workflow or change to the workflow allowlist is
required. It does not start an unattended permanent process. The
experiment and transport are assistant-authored; source emission and concrete
goal selection use existing YADO mechanisms. There is no evidence here for
consciousness, general intelligence, or invention of an unrestricted mind.
