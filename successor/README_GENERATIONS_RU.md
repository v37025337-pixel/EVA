# Исполняемые поколения компонентов Successor

`successor.generation` связывает архив всех веток, сохранённое состояние ядра,
измеряемый отбор компонентов и отдельный журнал активации. Поколение компонентов
0 использует родительские механизмы. Поколение 1 исполняет выбранную ядром
комбинацию механизмов логики, планирования, маршрутизации и синтеза программы.

Ядро читает выражения генов из двух известных форматов исторических отчётов
`g2-evolutionary-genome-v1.json` и `g2-evolutionary-multigeneration-lineage-v1.json`
на каждой ветке архива. Принимаются только записи, для которых исходник механизма
на этой же ветке побайтно совпадает с унаследованным текущим исходником.
Прочие файлы и история остаются доступными в полном архиве; они не получают
статус проверенной памяти автоматически. Исторические оценки PASS не влияют
на допуск. Произвольный код из архива не импортируется.

Отбор измеряет каждый вариант на заданных контрактах и отвергает потерю
родительского результата на защищённых случаях. В частности, проверяются
недоступный этап, отсутствующая зависимость, исчерпанная квота, достигнутая цель
и недостаточный бюджет. Ядро рекомбинирует победителей по отдельным компонентам.
Одинаковое качество разрешается в пользу меньшего выражения гена.

После сохранения кандидата создаются новые имена полей, знаки условий,
коэффициенты и запросы. Отбор на этой проверке не повторяется. Переход требует
успеха во всех четырёх измеряемых областях, улучшения минимум в двух, сохранения
защищённых результатов, повторного исполнения ранее принятых когнитивных задач
и аудита родительского ядра. Прежние отказы сохраняются как отказы. Проверка
памяти повторно исполняет обученный результат; она не восстанавливает процесс
его первоначального открытия. Контроль без архивных вариантов оставляет
родительскую архитектуру.

Булевы задачи проверяют новые комбинации несущественных признаков при известной
проекции таблицы истинности. Кодовые задачи проверяют перенос точного полинома
на новые аргументы вне обучающего диапазона. Это ограниченные инженерные
контракты, а не неизвестный внешний экзамен на общий интеллект.

Пример для уже существующего закрытого состояния родителя:

```bash
python -m successor.generation propose --manifest /path/birth/manifest.json --kernel-state /path/kernel.sqlite --archive /path/all-branches.sqlite --generation-state /path/generation.sqlite
python -m successor.generation admit --manifest /path/birth/manifest.json --kernel-state /path/kernel.sqlite --archive /path/all-branches.sqlite --generation-state /path/generation.sqlite
python -m successor.generation status --manifest /path/birth/manifest.json --kernel-state /path/kernel.sqlite --archive /path/all-branches.sqlite --generation-state /path/generation.sqlite
python -m successor.generation execute --manifest /path/birth/manifest.json --kernel-state /path/kernel.sqlite --archive /path/all-branches.sqlite --generation-state /path/generation.sqlite --input /path/task.json
```

Форматы входов и контрольные примеры находятся в `generation_tasks.py`.
Операция `rollback` с теми же аргументами состояния возвращает исполнение к
родительским компонентам. Активация атомарна с отчётом допуска; остановка процесса
до фиксации транзакции не оставляет частично активированного потомка. Повторное
открытие проверяет цепь событий и заново воспроизводит отбор и результаты допуска.

Существующий manifest, идентификатор и журнал родителя сохраняются. Новый журнал
отдельно привязывает архив, исходники связующего слоя и точный хвост памяти
родителя. Для переноса нужны оба журнала, manifest родителя, его архив и архив
всех веток. Для ещё одного отбора нужен новый журнал поколения; повторная
активация старого допуска после отката запрещена.

Связующий код, адаптеры и контракты проверок написаны ассистентом. Выражения
генов, отбор, комбинацию и поддерживаемые модели/программы получает само ядро.
Это исполняемое поколение компонентов Successor над каноническим G2. Формальный
переход control-plane в G3, произвольное самоизобретение архитектуры, общий разум
и сознание этим результатом не устанавливаются. Команды выполняют конечную
работу и сохраняют состояние; постоянный фоновый процесс не создаётся.
