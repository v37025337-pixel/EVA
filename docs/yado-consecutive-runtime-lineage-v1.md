# Consecutive bounded runtime capacity extensions

`successor.lineage.ConsecutiveLineage` closes one finite loop:

1. Select an existing, genuinely failed native-source goal from memory.
2. Exhaust all currently available strategies on the same specification with budget 30.
3. Materialize a reusable candidate using the inherited exact fitter.
4. Persist the candidate reference and fresh trial seed, then run the existing complete gates.
5. Admit the candidate and solve the same goal through ordinary cognition using that exact module.
6. Re-execute labelled examples and sealed queries; count one generation only after success.
7. Derive and execute the next challenge from the preceding successful program.

The only accepted objective contains `schema`, `objective`, and a requested count from 3 to 5. It cannot contain a selected goal, degree, program, coefficients, commands, or a claimed verdict. A request may stop before its target because the grammar, available deficit, gates, or retry do not support further progress.

```json
{
  "schema": "yado.consecutive-runtime-lineage.v1",
  "objective": "consecutive_verified_capacity_extensions",
  "generations": 3
}
```

The assistant authors the adapter, controller and finite composition grammar. The kernel selects concrete failures and candidate bounds from its journal. After a verified success it chooses composition parameters from the immutable finish hash and builds `x * parent(x) + a*x + b`. Its parent program is actually executed and independently cross-checked by exact Lagrange interpolation. Subsequent tasks are endogenous mathematical challenges; they are not additional raw external-world observations.

The supported family has one integer input, integer polynomial coefficients and maximum degree 5. Degree 0–3 emitter bytes and old proposal-selection behavior remain unchanged. New proposals explicitly record the degree-5 selection policy; degrees 4–5 use a versioned adapter. The inherited native route already supports some degree-3 polynomials, so increasing a degree bound or changing a source hash alone never qualifies as a gain.

## Durable evidence and stopping

`LINEAGE_*` records are checked semantically on every state verification. Their full prospective transitions are checked before insertion. The controller serializes ownership of the journal: unrelated goals, rollback, activation, upgrades, and overlapping sessions cannot silently intervene. Admission, gate attempt, failed control, successful retry, and preceding generation references bind actual ticks and event hashes.

Each generation permits one complete gate attempt. Its seed is committed before any trial or subprocess. Resuming an interrupted gate records terminal `WITHHOLD/INTERRUPTED_GATES`; it cannot choose another seed or discard an unsuccessful report. Other committed phases resume the same goal/proposal without duplicate generation counts. An implementation upgrade requires an idle lineage.

The comparison is a within-session capacity test. Control and treatment have the same specification and budget, and all old strategies must actually fail before admission. Self-model statistics can change after those failures; identical allocation statistics are not claimed. A post-success rollback is not used as the control because it would retain the newly learned source.

Full regression, fresh transfer against the inherited route and active parents, negative cases, actual retained-memory execution, and the complete kernel audit retain their existing requirements. Passing flags alone cannot replace program re-execution at generation counting.

## Entry points

```bash
python -m successor.lineage \
  --manifest /absolute/path/birth/manifest.json \
  --state /absolute/path/birth/kernel.sqlite \
  --workspace-id local-lineage \
  --issue-id YADO-1 \
  --generations 3 \
  --output /absolute/path/lineage-gates
```

For the existing local Hivemind transport, use `successor.hivemind_lineage.run_issue`. One real tracker issue carries the whole high-level objective. Per-generation runtime proposal keys are deterministic internal correlation keys, not claims that separate tracker issues exist. Tracker edits and cancellations stop active work durably; publication never overwrites an observed cancellation.

Results describe bounded runtime capacity extensions. They do not establish a new general cognitive architecture, unrestricted algorithm invention, G3, or consciousness.
